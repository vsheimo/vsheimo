# Протокол обновления базы знаний

Цель репозитория - постепенно собирать публичный образ компетенций: не статичное резюме, а живую систему, которая растет вместе с новыми текстами, проектами и кейсами.

## Как добавлять новый материал

1. Новый сырой материал кладется в `sources/inbox/` в формате markdown.
2. Имя файла: `YYYY-MM-DD-topic.md`.
3. В начале файла желательно указать источник: Telegram, заметка, документ, расшифровка, кейс, письмо, созвон, проект.
4. После добавления материала обновляются:
   - `README.md`, если появился новый публично важный акцент.
   - `PROFILE_LONGREAD_RU.md`, если изменилась большая история.
   - `COMPETENCY_MAP.md`, если появился новый навык, кейс или зона силы.
   - `CHANGELOG.md`, чтобы было видно, как меняется образ.

## Как перерабатывать сырье

Новый материал не нужно переносить дословно. Его нужно переваривать:

- вытащить факты;
- отделить эмоцию от компетенции;
- сохранить сильный авторский голос;
- убрать лишнее, что не работает на публичный образ;
- добавить в карту навыков только то, что действительно усиливает профиль;
- обновить README так, чтобы человек снаружи быстрее понимал, с кем имеет дело.

## Рабочий prompt для будущих обновлений

```text
Возьми новые файлы из sources/inbox и обнови публичный профиль Vlad Sheimo.

Нужно:
1. Найти новые компетенции, кейсы, проекты, инструменты и повторяющиеся мыслительные паттерны.
2. Обновить README.md, если материал усиливает публичное позиционирование.
3. Обновить PROFILE_LONGREAD_RU.md, сохранив стиль: богатый, плотный, живой, без стерильного корпоративного языка.
4. Обновить COMPETENCY_MAP.md структурно, без раздутых обещаний.
5. Добавить запись в CHANGELOG.md.
6. Не тащить в публичную часть лишнюю приватность, имена клиентов, токены, внутренние ссылки и сырые куски переписок.
```

## Правило публичности

В профиль попадает только то, что усиливает образ и не превращает репозиторий в мусорную корзину. Сырье может быть хаотичным. Публичная витрина должна быть точной.
