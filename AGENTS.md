# AGENTS

Этот репозиторий - рабочий контур цифрового следа Влада Шеймо: навыки, профиль, резюме, анкета, досье, Kwork, доказательства, стартеры и рыночные карты.

## Обязательный вход

Перед любой существенной задачей читать:

1. `starters/00_AUTOSTART_READ_FIRST_RU.md`;
2. `starters/PROJECT_AUTOSTARTER_STATE.md`;
3. доменный стартер по задаче.

Если задача про Kwork - дополнительно читать:

1. `starters/03_KWORK_MARKET_AND_PROFILE_RU.md`;
2. `market/2026-06-kwork-canon.md`;
3. `market/2026-06-debt-and-iterations.md`;
4. `spouse_kwork/README.md`;
5. `vlad_kwork/README.md`.

Если задача про таблицы - читать:

1. `starters/02_BIG_MAP_SPREADSHEET_CANON_RU.md`;
2. исходники данных;
3. файлы источников и долгов.

## Правило результата

Нельзя отвечать только из памяти. Нужен хотя бы один из типов evidence:

1. прочитанный файл;
2. команда и ее результат;
3. ссылка на источник;
4. созданный или измененный артефакт;
5. явно помеченное `ПРОВЕРИТЬ`, если факт не доказан.

## Табличный канон

Пользователь предпочитает одну большую карту вместо множества мелких вкладок.

Для таблиц:

1. первая вкладка - `Карта проекта`;
2. raw/live/source слои сохраняются отдельно;
3. источники и долги отдельными вкладками;
4. видимая зона на русском;
5. без длинных тире;
6. без потери строк и фактов;
7. деньги и часы считаются, а не угадываются.

## Роли

Роли используются как проверка, а не как театр:

1. Архивариус;
2. Фактолог;
3. Сборщик навыков;
4. Методолог;
5. Бизнес-архитектор;
6. Финансовый критик;
7. Офицер риска;
8. Оппонент;
9. Переводчик оператора.

Оппонент должен остановить ранний PASS, если результат красивый, но не соответствует задаче.

## Git

1. Не использовать `git add .` и `git add -A`.
2. Не трогать изменения пользователя, если они не относятся к задаче.
3. Не переписывать `*-LIVE`.
4. Коммитить только файлы текущей задачи.
5. Kwork сейчас остается в этом репозитории. Отдельный Kwork-репозиторий создавать только по правилу `starters/04_REPOSITORY_ROUTING_RU.md`.
