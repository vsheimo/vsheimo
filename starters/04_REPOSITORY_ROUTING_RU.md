# 04 Repository Routing

Status: `CURRENT_REPO_DECISION`

Дата решения: 2026-06-17.

## Проверено

Через GitHub CLI проверен список репозиториев `vsheimo`.

Отдельного репозитория под Kwork сейчас нет.

Есть:

1. `vsheimo/vsheimo`;
2. `vsheimo/neutral-ai-project-starter`;
3. `vsheimo/spreadsheet-cfo-rules-template`;
4. другие проектные репозитории, не являющиеся Kwork-центром.

## Решение

Kwork, профиль, навыки, резюме, анкета, досье и рыночные карты сейчас живут в `vsheimo/vsheimo`.

Причина:

1. Kwork напрямую связан с навыками Влада и Насти;
2. Kwork использует доказательства из профиля, источников, архивов и GitHub;
3. отдельный репозиторий сейчас разорвет контекст;
4. оператору нужна одна большая карта, а не еще одна точка входа;
5. текущие файлы уже находятся в `market/`, `spouse_kwork/`, `vlad_kwork/`, `prompts/`.

## Когда создавать отдельный Kwork-репозиторий

Создать отдельный репозиторий можно только если выполнены условия:

1. 3-7 дней есть живые данные по откликам, просмотрам и конверсии;
2. появились опубликованные кворки;
3. есть повторяемый процесс ежедневного поиска заказов;
4. Kwork-пакет стал самостоятельным продуктом, а не частью профиля;
5. все приватные доказательства отделены от публичных;
6. оператор явно подтверждает split.

## Где хранить сейчас

1. `market/` - рынок, заказы, конкуренты, экономика, источники, долги.
2. `spouse_kwork/` - тексты, обложки, FAQ и карточки Насти.
3. `vlad_kwork/` - тексты и карточки Влада.
4. `prompts/` - большие промты и starter-промты.
5. `starters/` - правила проходов и автозапуска.
6. `sources/` - входящие доказательства, если они безопасны для репозитория.

## Git-гигиена

1. Не использовать `git add .`.
2. Коммитить только файлы текущей задачи.
3. `*-LIVE` не переписывать.
4. Сырье от Claude не считать догмой.
5. Если файл чужого лейна нужен как источник - читать и ссылаться, а не перезаписывать.
6. Если возник конфликт - создать новый файл с суффиксом `-CODEX` или спросить оператора.
